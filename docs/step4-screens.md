# 画面一覧

サービス名: 決済メール解析による自動家計簿サービス
対応する仕様書: [step2-api-spec.md](./step2-api-spec.md)（API ID はこの仕様書の番号）
画面遷移図: [step4-transition.md](./step4-transition.md)

> - フロントエンドの URL は `http://localhost:5173` を起点とする（バックエンドの `DEFAULT_REDIRECT_URI` と揃えている）
> - API はフロントの開発サーバのプロキシ経由で**同一オリジン**として呼ぶ（`/api/...`）。API は CORS ヘッダを返さないため（API 仕様書 2 章）
> - **「未分類」は `category_id = NULL` で表す**（カテゴリ `未分類` は作らない。API 仕様書 API-003 の注記）。画面では `category` が `null` の取引を「未分類」と表示する
> - 関連 API のパスは共通の `/api/v1` を省略して書く
> - `実装フェーズ` は API 仕様書 5 章の同名の列に合わせる。**コア**は Step 6 で実装する範囲、**拡張**は Step 8 以降
> - ダイアログ（確認・入力用のモーダル）は独立した画面にせず、呼び出し元の画面の「主要な要素」に含める

## 3. コア画面の詳細

Step 5（画面レイアウト設計）と Step 6（実装）の入力になるよう、表示・入力する項目と API のフィールドの対応を示す。

### SCR-001 ルート

| 条件 | 遷移先 |
|---|---|
| トークンがあり、API-004 が `200` | SCR-010 取引一覧（拡張後は SCR-030 ダッシュボード） |
| トークンがない、または API-004 が `401` / `404 USER_NOT_FOUND` | SCR-002 ログイン |

### SCR-002 ログイン

| 要素 | 内容 |
|---|---|
| 「Google でログイン」ボタン | `/api/v1/auth/google?redirect_uri=http://localhost:5173/auth/callback` へ**ブラウザごと遷移**する（fetch ではない。プロキシ経由で API-002 に届く） |
| エラーメッセージ | SCR-003 から渡されたエラーコードに応じて表示する（`ACCESS_DENIED`: 同意が必要な旨、`INVALID_STATE`: やり直しを促す、`TOKEN_EXPIRED`: 有効期限が切れた旨） |
| ログイン済みで開いた場合 | 画面を出さず SCR-010 へ |

### SCR-003 ログイン処理中

表示は「ログインしています…」のみ。画面を開いた瞬間に以下を順に行う。

1. URL フラグメントから `access_token`（失敗時は `error`）を取り出す
2. **`history.replaceState` でフラグメントを URL から消す**（ブラウザの履歴・画面共有にトークンを残さない）
3. トークンを保存し、API-004 で有効性を確認する
4. ログイン前に開こうとしていたページ（`return_to`）があればそこへ、なければ SCR-010 へ遷移する

> `return_to` は `sessionStorage` に保存し、**`/` で始まり `//` で始まらないパスのときだけ**使う。
> 外部サイトの URL を入れられるとオープンリダイレクトになるため。

### SCR-010 取引一覧

| 要素 | 内容 | API のフィールド |
|---|---|---|
| 期間 | 開始日・終了日。既定は当月 1 日〜今日 | API-010 `from` / `to` |
| カテゴリ | プルダウン。先頭に「未分類」を置く | API-010 `category_id`（選択肢は API-019。「未分類」は `category_id=none`） |
| 決済手段 | プルダウン | API-010 `payment_method_id`（選択肢は API-031） |
| キーワード | 店舗名・メモの部分一致 | API-010 `q` |
| 件数・合計 | 「42 件 / 合計 ¥38,450」 | `meta.total` / `meta.total_amount_minor` |
| 一覧の行 | 日時・店舗名・カテゴリ・決済手段・金額。行を押すと SCR-012 | `data[]` の `occurred_at` / `merchant.name` / `category.name`（`null` は「未分類」） / `payment_method.name` / `amount_minor` |
| 速報の印 | 確定前の金額であることを示す | `data[].status = pending` |
| ページ送り | 20 件ずつ | `limit` / `offset`、総ページ数は `meta.total` から算出 |
| 「登録」ボタン | SCR-011 へ | - |

> 絞り込み条件は **URL のクエリに持つ**（`/transactions?from=2026-09-01&category_id=3`）。
> 詳細から戻ったときに条件が保たれ、条件つきの一覧をブックマークや共有もできる。

### SCR-011 取引登録

| 要素 | 必須 | 既定値 | API のフィールド | 画面側の検証 |
|---|---|---|---|---|
| 日時 | ○ | 現在時刻 | `occurred_at`（`+09:00` を付けて送る） | 未来日時は警告のみ |
| 金額 | ○ | - | `amount_minor` | 1 以上の整数 |
| 店舗名 | - | - | `merchant_name`（既存になければサーバが作成） | - |
| カテゴリ | - | 未分類 | `category_id`（未分類のときは送らない） | - |
| 決済手段 | - | 現金 | `payment_method_id` | - |
| メモ | - | - | `note` | 500 文字以内 |

- 通貨は入力させない（`JPY` 固定。サーバは `JPY` 以外を `400 UNSUPPORTED_CURRENCY` で弾くため）
- 送信中はボタンを無効にし、二重登録を防ぐ
- `400 INVALID_AMOUNT` は金額欄の下に、`404 CATEGORY_NOT_FOUND` などは画面上部に表示する
- 登録に成功したら SCR-010 へ戻り、「登録しました」と表示する

### SCR-012 取引詳細

| 要素 | API のフィールド | 補足 |
|---|---|---|
| 日時・金額 | `occurred_at` / `amount_minor` | - |
| 店舗 | `merchant.name` / `merchant.address` | 「この店舗の取引を見る」→ `SCR-010?merchant_id=…` |
| カテゴリ | `category.name` / `category_source` | `null` は「未分類」。由来を「自動分類」「手動」で表示する |
| 決済手段 | `payment_method.name` | - |
| 取込元 | `source` | 「メール」「手入力」 |
| メモ | `note` | - |
| 元になったメール | `payment_events[]` | **拡張**。Step 6 時点では常に空のため表示しない |
| 「マージ解除」ボタン | API-016 | **拡張** |
| 「削除」ボタン | API-014 | 確認ダイアログで OK を押したら削除し、SCR-010 へ |

| API の結果 | 画面の挙動 |
|---|---|
| `404 TRANSACTION_NOT_FOUND` | SCR-099（「取引が見つかりません」） |
| `403 FORBIDDEN` | SCR-099（「この取引は表示できません」） |
| `409 ALREADY_MERGED`（削除時） | ダイアログ内に「マージを解除してから削除してください」 |

### SCR-013 取引編集

SCR-011 と同じ入力欄を使い、API-012 の値を初期値にする。**変更した項目だけを API-013 に送る**（API-013 は送った項目だけを更新するため）。

- カテゴリを「未分類」に戻したときは `category_id: null` を送る（決済手段を外す・メモを消す場合も同様に `null`）

- **店舗名は表示のみで変更できない**。API-013 は `merchant_id` しか受け付けず、店舗を選ぶための一覧（API-022）が拡張フェーズのため（[提出物](./step4-submission.md)の相談事項）
- 「今後の同じ店舗にも適用する」チェックボックス（`learn_category`）は**拡張**。Step 6 では表示しない
- 保存に成功したら SCR-012 へ戻る

### SCR-020 カテゴリ管理

| 要素 | API のフィールド | 補足 |
|---|---|---|
| 一覧 | API-019 `include_counts=true` | 親の下に子を字下げして表示、`sort_order` 順 |
| 取引件数 | `transaction_count` | 削除確認で使う |
| 初期カテゴリの印 | `is_system` | `true` は削除ボタンを出さない |
| 作成 / 編集ダイアログ | API-020 / API-021 PUT の `name` / `parent_id` / `sort_order` | 親の選択肢から自分自身と子孫を除く（サーバの `400 INVALID_PARENT` に頼る前に防ぐ） |
| 削除確認ダイアログ | API-021 DELETE | 「このカテゴリの取引 12 件は未分類になります」と件数を示す |

| API の結果 | 画面の挙動 |
|---|---|
| `409 DUPLICATE_CATEGORY_NAME` | 名前欄の下に「同じ名前のカテゴリがあります」 |
| `400 INVALID_PARENT` | 親の欄の下に表示 |
| `400 SYSTEM_CATEGORY_NOT_DELETABLE` | 通常は起きない（ボタンを出さないため）。起きたら画面上部に表示 |

## 5. Step 0 の画面案との対応

Step 0（[step0-pipeline.md](./step0-pipeline.md) 5 章）で挙げた画面案が、本一覧のどの画面になったか。
**変えた点・対象外にした点**を明示する。

| Step 0 の画面 | 本一覧の画面 | 差分 |
|---|---|---|
| ダッシュボード | SCR-030 | - |
